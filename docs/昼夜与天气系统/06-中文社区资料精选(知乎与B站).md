### 1.【雷火LGDC系列】游戏开发中呼风唤雨的魔法(上篇):天气系统设计与实践
- **作者**:网易游戏雷火事业群(作者"布鲁斯",参与《逆水寒》《逆水寒手游》《永劫无间手游》)
- **链接**:https://zhuanlan.zhihu.com/p/21707980913 (2025-02,121 赞)
- **要点**:
  - 天气系统 = **TOD(Time of Day)**,本质是"环境控制系统":基于时间、天气、剧情动画、gameplay、区域等**切换不同的环境配置**。
  - 功能二分:**环境表现**(光照/主光/环境光/GI、天空/物理大气/手绘天空盒、云/2D云/程序噪声体积云/云海/粒子面片云、雾/大气雾/指数高度雾/体积雾/灯光雾、雨雪粒子/潮湿波纹积雪/形变雪、日月星极光风)与**逻辑处理**(插值、覆盖)。
  - 体积云分两大流派:**过程噪声体积云**(TrueSKY、《地平线》系列、《荒野大镖客》)vs **物理模拟体积云**(UE5 VDB Clouds、Nubis3)。
  - 形变雪(踩雪坑)两大方案:拍摄绑定角色的 anchor vs 拍摄导致形变的对象;渲染上曲面细分 vs 视差映射写深度——《战神》最新作从视差映射改回了曲面细分。
  - 逻辑层难点:时间线环境插值过渡、副本/剧情对外部环境的覆盖、雨雪参数只覆盖时间线一部分、两环境渲染开关不一致、难插值的参数(贴图)、昼夜切换双主光对大气与体积云的处理。
  - 架构:**组件化**——每个 feature(如 Atmosphere、VolumetricCloud)对应 FeatureComponent + FeatureRenderer + DefaultSetting,注册到 EnvironmentMgr;环境配置只记录"开启覆盖的 feature";插值代码用 Roslyn Source Generator 自动生成。(Unity 实现,思想可平移到 UE)
- **对本项目价值** ★★★★★:架构蓝图(feature 组件化 + 插值/覆盖逻辑)与"容易踩的坑"清单最值得抄。

### 2. UE中的天气系统方案介绍(腾讯魔方,已上线《暗区突围》)
- **作者**:腾讯魔方引擎中心
- **链接**:https://zhuanlan.zhihu.com/p/533293862 (2022-08,179 赞)
- **姊妹篇**(GDC 演讲整理):[如何在手机上做出了主机级别的天气系统](https://zhuanlan.zhihu.com/p/525326786) / [微信公众号版](https://mp.weixin.qq.com/s/_YJmkNUV1t3K1vg1JC2iqA)
- **要点**:
  - **SkyAtmosphere 移动端优化**:UE 每帧用 Compute Shader 生成 4 张 LUT(透光度、多重散射、天空视图、3D 大气透视);魔方舍弃 3D LUT 用高度雾替代 → 全部 2D LUT 可用 Pixel Shader 更新;分帧计算;天空视图 LUT 半八面体参数化省 50% 光线行进——总 GPU 从 1.35ms 降到 0.77ms(约 -40%)。
  - **体积云**:Worley 3D 噪声(基础-细节两层)建密度 + **Weather Map**(2D Cloud Mask,材质驱动绘制,全局云覆盖率/云类型两个参数控制)+ **Cloud Profile**(不同类型云在不同高度的形状,用 UE 曲线工具生成贴图)。
  - **云光照**:单次散射(双 HG 相位函数混合)、天空环境光(随高度)、地面环境光(模拟地表反射)、多重散射(参考 Frostbite 近似法 + 《地平线》暗边 dark edge)。
  - **性能**:结果缓存到 512×512 半八面体 RT、双 RT 交换分帧更新、棋盘格渲染省 50%、切片分帧+方向插值、TAA 式时序升采样、压缩进 RGBA8;iPhone 11 上从 ~10ms 优化到 <1ms。云影直接用缓存 RT 投射。
  - **闪电三阶段**:Lightning Leader(分形算法建通道,转四边形网格,顶点颜色存主干/距离信息做生长动画)→ Return Stroke(主光按距离增强亮度照亮场景)→ Re-Strike(2-4 次闪烁)。云层照亮通过与云层求交近似。
  - **雨天**:粒子雨;湿润效果参考《神秘海域4》Waylon 的材质参数法;遮挡贴图用 CSM Scrolling 快速更新。
  - **天气定义方式(亮点)**:不硬编码"天气参数结构体",而是用 **Level Sequence 采样任意属性**;多个 Sequence 图层式叠加,每层有"不透明度",天气预设就是一组不透明度配置(像 Photoshop 图层),gameplay 切天气 = 在不透明度之间过渡。
  - **天体系统**:输入一天内时间、年积日、时区、经纬度 → 自动定位太阳/月亮方向。
  - 架构建议:**不要做开箱即用的整体方案**(UE 材质/蓝图是二进制,多项目分支难维护),拆成 Component + Material Function,Feature 注册到全局天气 Subsystem 互相查询。
  - 文末引用清单:Nubis(Decima)、Oz: The Great and Volumetric、Frostbite 体积渲染/天空大气、Uncharted 4 TA、CSM Scrolling、Volumetric Atmospheric Scattering 等。
- **对本项目价值** ★★★★★:与"UE + SkyAtmosphere + 体积云"技术路线完全同构,闪电三阶段建模可直接套用到 Niagara。

### 3. 【Unreal从0到1】4.1 游戏中的天气系统漫谈
- **作者**:从巴洛克到浪漫的你
- **链接**:https://zhuanlan.zhihu.com/p/409617280 (2021-09,140 赞)
- **要点**:
  - 开放世界标配:昼夜循环、体积云、环境可交互的雨雪。
  - 自研主机项目天气框架要考虑五大块:渲染管线定制(大气散射、体积云、雾、后处理、贴花)、地形材质混合(积雪/水洼)、场景光照与 GI(天空光正确反馈到不同材质)、逻辑&数据驱动的材质方案(Procedural Skybox)、粒子系统(风沙雨雪)。
  - 推荐参考方案:Azure Dynamic Sky(Unity,考虑黄道夹角,全局+局部天气)、**Ultra Dynamic Skybox**(UE4,功能最全但重)、Easy Sky(UE4 轻量非物理)、Sylized Weather(UE4 轻量可移植,PBR/NPR 双版本)。
  - 游戏案例:《地平线》《荒野大镖客》《战地》;移动端 PBR 看《天涯明月刀》,卡通渲染看《原神》(作者逆向过原神天空盒/云/雨:技术上无黑科技,美术把控好)。
  - 《Halo》较早提出"远景天空情绪版"与"嵌套式天空盒"处理大海拔变化。
- **对本项目价值** ★★★★:方案选型对比视角好,适合作为"我们要做多重"的决策参考。

### 4. 用UE4做大世界2 —— 无缝过渡的动态天气和 UE4 的体积云
- **作者**:繁弱
- **链接**:https://zhuanlan.zhihu.com/p/447034377 (2021-12,66 赞)
- **要点**:
  - 需求:15 种天气平滑过渡;性能预算(云 2ms、雨 0.5ms);**编辑器阶段可直接预览**;网游闪电同步。
  - 天气元素构成(全部 UE 原生):日光、月光、**闪电专用定向光**、月亮、星空、SkyAtmosphere、风源、高层云、体积云、体积雾、指数雾、粒子管理、雨效管理、后期处理。
  - **数据驱动方式**:美术把所有天气属性汇总,每个属性一条曲线(float → FloatCurve,vector/rotation → LinearColorCurve);每种天气一组"24 小时循环数据"+一组"过渡数据"(如地面变湿强度、雨丝速度);改造引擎让曲线可继承,天气数据可复用。
  - 运行时:属性名 → Property 指针缓存;天气切换时对上一个状态做 snapshot,多 snapshot 按优先级同时插值 → 平滑过渡。
  - 三层云:层云/积云用 UE 体积云(参考《地平线》《大镖客》做法:基础塑形 = Perlin+Worley 噪声贴图 + 128×1 Height Curve + Remap → ConservativeDensity;细节侵蚀 = volume texture 多 mip 多次采样),高层云用 2D 云纹理叠天空盒。
  - 体积云性能细节:ConservativeDensity 为 0 时提前退出;预烘焙多 octave 噪声减少运行时采样;谨慎开 GroundContribution/Cloud Shadow;Height Curve Atlas 可改小。星星/月亮用与高层云同一张 Mask 取反剔除,做出"云挡住星月"。
- **对本项目价值** ★★★★★:与本项目路线最接近的原生 UE 实现;"曲线 + 快照插值"是天气过渡的标准答案。

### 5. 用UE4做大世界3 —— 雨天、闪电、水体的效果实现
- **作者**:繁弱
- **链接**:https://zhuanlan.zhihu.com/p/447061204 (2022-01,102 赞)
- **要点**:
  - 雨天状态机:地面潮湿(改 GBuffer roughness/basecolor)→ 积水(改 Normal,交错混合法线贴图)→ 涟漪(flipbook)→ 流水(世界空间 XZ/YZ 双平面映射),雨停反向播放。
  - **雨丝**:先做后处理(相机前套纺锤体,性能稳但雨量极端时穿帮),后改 **Niagara 粒子在相机周围生成**(性能随粒子数波动但效果更好)——两种路线的取舍过程有参考价值。
  - **雨的遮挡**:新增 DepthOnlyRender + TopView OcclusionPass,每帧拍 256×256 depth map,Camera Space 算遮挡,边缘 PCF + Bias 防自遮挡。
  - **闪电**:梯级先导(分形)**用 Niagara 粒子实现**;回击 = 主干高亮度闪烁 + 照亮场景 + 按闪电位置投射方向阴影;全程雷声(轰鸣 + 雷击)。
  - 参考文章:Sebastian Lagarde《Water drop 2b – Dynamic rain and its effects》(https://seblagarde.wordpress.com/2013/01/03/water-drop-2b-dynamic-rain-and-its-effects/ )、[网易雷火:如何打造"最美下雨天"](https://zhuanlan.zhihu.com/p/111904859 )、《天涯明月刀》雨景渲染(https://gameinstitute.qq.com/community/detail/100054 )。
- **对本项目价值** ★★★★★:Niagara 雨丝 + Niagara 闪电梯级先导的直接实现案例。

## 三、中文资料要点小结(对"我们该怎么做"的启示)

1. **功能范围共识**(知乎多家方案一致):太阳/月亮方位与光照 → 天空大气 → 体积云 → 雾 → 雨雪粒子 → 地表潮湿/积雪 → 雷电 → 风 → 后处理 → 音频 → 玩法接口。
2. **数据驱动的两种主流做法**:
   - 曲线驱动:每属性一条 Curve,每天气一份 24h 曲线集 + 过渡曲线(繁弱 / UDS);
   - Sequence 图层驱动:Level Sequence 采样任意属性,多 Sequence 按"不透明度"叠加(腾讯魔方)。
3. **过渡统一解法**:切换时 snapshot 当前值,多状态按优先级插值(繁弱);或权重混合多个"天气预设"(UDS/魔方)。
4. **Niagara 的分工**:雨丝(相机空间粒子)、雪、闪电梯级先导(分形粒子)、环境氛围粒子(飘叶/沙尘);湿滑/积雪走材质参数而非粒子。
5. **性能共识**:体积云给 ~2ms、雨粒子 ~0.5ms 的预算;能分帧/降采样/缓存就分帧。
