# 对本项目的启示:实现路线建议

> 本文件是对前述调研(概念、UE 方案、开源、游戏、演讲、中文社区)的综合,结合本仓库现状(DreamFXLang 文本化 Niagara 工作流 + UE5)给出下一步建议。这是资料调研的结论页,不是最终设计文档。

## 一、系统的总体形态(共识架构)

```
┌─────────────────────────────────────────────────────────┐
│                    天气/昼夜管理器(单例/WorldSubsystem)      │
│   游戏时间(可配倍率)  天气状态机(状态+权重)  调度(随机/脚本/档期)  │
└───────┬──────────────┬───────────────┬──────────────────┘
        │ 时间驱动       │ 状态/权重混合     │ 事件(打雷/降雨开始)
        ▼              ▼                ▼
┌──────────────┐ ┌────────────────┐ ┌──────────────────────┐
│ 昼夜层(基线)   │ │ 天气层(修正量)     │ │ 事件表现              │
│ 太阳/月亮方位   │ │ 云量/雾密度/风/雨雪  │ │ 闪电三阶段/雷声延迟     │
│ 光照颜色强度    │ │ 湿度/雪量/积水      │ │ 阵风/落叶/沙尘        │
│ SkyAtmosphere │ │ 后处理/音频淡入淡出   │ │ 雨滴溅落(表面粒子)     │
│ 曝光           │ │                │ │                     │
└──────┬───────┘ └───────┬────────┘ └──────────┬───────────┘
       │                 │                     │
       ▼                 ▼                     ▼
┌─────────────────────────────────────────────────────────┐
│  参数汇聚层:MPC(湿度/雪量/风强/云覆盖率…) + Curve 集(24h 曲线)  │
│  SkyAtmosphere ← 太阳角度;VolumetricCloud ← 云参数;PostProcess  │
│  Niagara 系统 ← 事件/持续参数(雨丝/雪/闪电/溅落/雾灵)             │
│  地表材质 ← MPC(Wetness/Snow)驱动 roughness/法线/积水/积雪      │
└─────────────────────────────────────────────────────────┘
```

关键原则(多家方案一致):
1. **昼夜是基线,天气是修正量**——两层解耦,互不嵌套,统一由管理器广播"环境状态"。
2. **所有跨系统参数走 MPC / Curve**,不要逐个材质实例改参数;湿度、雪量、云覆盖率、风强是最小核心参数集。
3. **过渡 = snapshot 插值**(繁弱)或 **Sequence/预设权重混合**(魔方、UDS、SequenceBlender);禁止瞬间切换,过渡期 1–3 秒起步,雨雪地面积累用更长的渐变曲线。
4. **Niagara 只管表现,判定归全局状态**(塞尔达的启示):湿滑、导电、可燃是全局状态传播,粒子只做视觉。

## 二、UE5 组件选型(结合本项目)

| 模块 | 选型 | 说明 |
|---|---|---|
| 天空 | **Sky Atmosphere**(原生) | 物理散射,LUT 化性能可接受;夜间配合月光 |
| 云 | **Volumetric Cloud**(原生) | Conservative Density 提前退出控性能;云影用 Beer Shadow Map |
| 光照 | DirectionalLight×2(太阳/月亮,Atmosphere Sun Light 0/1)+ SkyLight RealTimeCapture | 双主光是昼夜切换的标准做法(雷火文章提到双主光对大气/云的处理) |
| 太阳方位 | 自写时间驱动(简化)或 Sun Position Calculator(拟真) | 项目优先做"游戏时间 + 倍率",拟真经纬度可后置 |
| 雾 | Exponential Height Fog + Volumetric Fog | 天气状态改 Fog Density / 高度,廉价有效 |
| 雨/雪 | **Niagara**(相机包裹体积粒子) | 雨丝/雪花在相机周围生成;溅落/涟漪表面粒子;室内 Kill Sphere/遮挡 |
| 闪电 | **Niagara 分形束 + 定点强光 + 曝光脉冲 + 延迟雷声** | 三阶段:Leader(分形生长)→ Return Stroke(照亮)→ Re-Strike(闪烁 2-4 次) |
| 湿地/积雪 | 材质层 + MPC 参数(非粒子) | Wetness 压 Roughness、水坑法线、涟漪 flipbook;积雪层混合 |
| 风 | WindDirectionalSource + 全局风参数 | Niagara、植被、布衣共享同一风源(战神/对马岛结论) |
| 状态管理 | 自研 WorldSubsystem + Curve 集(或借鉴 SequenceBlender) | 每属性一条 24h 曲线;天气预设 = 曲线集/Sequence 组合 |

## 三、与本仓库 DreamFX 工作流的结合点

本仓库的特长是 **DreamFXLang 文本化 Niagara(.dfs/.dfe/.dfm)**,因此:

1. **Niagara 侧全部文本化**:雨丝、雪花、闪电束、溅落、涟漪触发器、雾灵、风沙等粒子系统全部用 `.dfs` 编写,纳入 `dfx.ps1 build` 流程,可版本管理、可 diff、可重建——这正好避开"UE 材质/蓝图是二进制、多分支难维护"的痛点(腾讯魔方架构建议)。
2. **管理器与数据层用蓝图/引擎原生**:天气管理器(WorldSubsystem)、MPC、曲线资产保持引擎原生,与 DreamFX 粒子通过用户参数(User Parameter)对接——DreamFX 生成的系统暴露一组用户参数(雨强、风强、浑浊度…),由管理器每帧/每事件写入。
3. **分阶段落地**(参考各家功能共识):
   - **M1 昼夜基线**:时间管理器 + 双定向光 + SkyAtmosphere + SkyLight + 曝光曲线;产出"一天 24h 时光循环"。
   - **M2 静态天气切换**:3-5 种天气预设(晴/多云/雨/雾),MPC 参数 + 过渡插值,体积云参数联动。
   - **M3 雨雪粒子**:Niagara 雨丝/雪 + 表面溅落 + 湿地材质参数;雷雨加入闪电三阶段 + 延迟雷声。
   - **M4 地表积累与玩法接口**:湿地渐变、积雪 RT(可选)、天气事件广播(Gameplay 监听)。
   - **M5 调优**:性能预算(参考:云 ~2ms、雨 ~0.5ms)、自动化"时段×天气"截屏矩阵(巫师 3 教训)。
4. **可用 DreamFX 验证的特性**:闪电分形生长(粒子生成网格束/光束渲染器)、雨滴涟漪(表面事件+法线扰动)、雨云底部的雨幕面片、雾中光柱(网格体粒子)。

## 四、性能与质量红线(来自调研的量化参考)

- 体积云预算 ~2ms(PC);`ConservativeDensity=0` 提前退出;少开 GroundContribution / Cloud Shadow(成倍增加 raymarching)。
- 雨/雪粒子预算 ~0.5ms;粒子数分级(高/中/低配),碰撞方式按需选择(简单碰撞 CPU / 距离场 GPU / 无碰撞)。
- SkyLight RealTimeCapture 用 9 帧时间切片分摊。
- 移动端若需支持:SkyAtmosphere LUT 分帧 + 半八面体化可省 ~40% GPU(魔方数据);体积云缓存到低分辨率 RT 分帧更新。
- 闪电光照用"局部强光 + 衰减半径"替代全屏泛光,防帧率骤降;雷声按距离延迟(343 m/s)。
- 天气状态入存档;时间缩放/暂停/倒流要与天气物理量积分一致(否则混合态失真)。

## 五、风险与已知坑(调研中反复出现)

1. **阴天最难做**:GI 下阴天易"平",黑神话都承认没做好——早期就做阴天 GI 验证。
2. **双主光过渡穿帮**:昼夜切换瞬间太阳/月亮交接,注意 SkyAtmosphere 索引与强度交叉淡化。
3. **贴图等不可插值参数**:两环境渲染开关不一致(一个开 2D 云一个关)需要明确的"并集开启 + 权重置零"策略。
4. **后处理是帧率大头**:屏幕雨滴、色彩分级要按设备档位降级。
5. **UDS 类插件很重**:如果买 UDS 只为参考,注意其蓝图体量;自研路线反而更贴合 DreamFX 文本化工作流。
